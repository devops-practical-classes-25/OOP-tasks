# Задание №3 - Online библиотека

Реализация принципов OCP и LSP в системе онлайн-библиотеки

## Поставнока задачи

Разработать систему управления онлайн-библиотекой, которая поддерживает добавление новых форматов книг без изменения существующего кода и соблюдает принципы открытости-закрытости (OCP) и подстановки Барбары Лисков (LSP).

## Требования к реализации

1. Базовый класс и интерфейс:
   + Реализовать класс `Book` в папке `Models`, содержащий основные свойства книги (название, автор, год издания).
   + Ввести интерфейс `IBookFormat` в папке `Interfaces`, определяющий метод `DisplayInfo()`, который будет реализован различными форматами книг.
2. Принцип открытости-закрытости (OCP):
   + Реализовать класс `PhysicalBook`, наследующий `Book` и реализующий `IBookFormat`. Этот класс должен хранить информацию о количестве экземпляров в наличии
   + Реализовать класс `DigitalBook`, наследующий `Book` и реализующий `IBookFormat`. Включить информацию о ссылке для скачивания.
   + Расширить систему возможностью добавления новых форматов книг без изменения логики существующих классов.
3. Принцип подстановки Барбары Лисков (LSP):
   + Убедиться, что классы `PhysicalBook` и `DigitalBook` могут использоваться везде, где ожидается базовый класс `Book`.
   + Гарантировать, что объекты производных классов корректно обрабатываются независимо от их типа (физическая или цифровая книга)

## Теоретический материал

### Принцип открытости-закрытости (OCP)

Принцип открытости-закрытости (OCP) является одним из пяти принципов SOLID и гласит, что:
 ```
Модули (классы, функции, модули и т.д.) должны быть открыты для расширения, но закрыты для модификации.
 ```
Это означает, что поведение системы должно быть легко изменяемым путем добавления нового кода (например, новых классов), а не изменения существующего. Важно, что добавление нового функционала не должно нарушать работоспособность уже существующего кода.

**Реализация OCP в примере:**

+ **Базовый класс `Book`** содержит общие свойства для всех типов книг, такие как название, автор, год издания. Он закрыт для изменений, поскольку если бы мы захотели добавить новый формат книги, не меняя этого класса, то могли бы создать новый класс, например, `AudioBook`, который будет реализовывать поведение для нового формата, не изменяя существующий код.
+ **Классы-наследники (`PhysicalBook`, `DigitalBook`)** реализуют специфическую логику для разных форматов книг, но базовый класс Book не требует изменений.

### Принцип подстановки Барбары Лисков (LSP)

Принцип подстановки Барбары Лисков (LSP) также является частью принципов SOLID и гласит, что:
```
Объекты производных классов должны быть взаимозаменяемыми с объектами базового класса без изменения корректности программы.
```
Это означает, что если класс A является базовым, а класс B — его наследником, то в любом месте, где используется объект класса A, можно подставить объект класса B, и программа должна работать корректно.

Принцип LSP фокусируется на том, чтобы производные классы не изменяли поведения, которое ожидается от их базового класса. Проще говоря, если где-то в коде ожидается объект типа `Book`, то объект типа `PhysicalBook` или `DigitalBook` должен быть заменяемым, и программа должна продолжать работать корректно.

**Реализация LSP в примере:**

+ У нас есть базовый класс `Book` с методами, которые подходят для всех типов книг (например, `Title`, `Author`, `Year`). Методы этого класса могут быть использованы и для объектов типов `PhysicalBook` и `DigitalBook`, так как эти классы наследуют все свойства и поведение базового класса `Book`.
+ Все производные классы, такие как `PhysicalBook` и `DigitalBook`, реализуют метод `DisplayInfo()`, который предоставляет информацию о книге. Программу можно спокойно расширять, добавляя новые форматы, при этом гарантируя, что новые классы будут корректно работать в местах, где используется базовый класс `Book`.
